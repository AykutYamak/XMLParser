# XML Parser

Конзолно приложение на C++ за парсване, редактиране и XPath търсене в XML документи. 
Проектът е разработен като курсова работа и демонстрира задълбочени познания по Обектно-ориентирано програмиране (ООП), управление на динамична памет и дизайн шаблони.

## Архитектура
Проектът е разделен на две основни части:
* **XML Core:** Съдържа бизнес логиката (`XmlDocument`, `XmlElement`, `XmlText`) и поддържа дървовидната структура. Включва собствено управление на паметта с каскадни деструктори и Move семантики.
* **CLI Commands:** Използва *Command Pattern* за управление на потребителския вход, което прави добавянето на нови функционалности лесно и безопасно (спазвайки Open-Closed Principle).
* **Exceptions:** Съдържа клас Exception, който наследява std::exception и служи като основа за специфични видове изключения.

## Поддържани команди
* `open <file>` - Зарежда XML файл в паметта.
* `close` - Изчиства паметта и затваря документа.
* `save` / `saveas <file>` - Запазва промените.
* `print` - Извежда форматирано (pretty-print) дървото.
* `select <id> <key>` - Извлича стойност на атрибут по дадено ID.
* `set <id> <key> <value>` - Добавя или променя атрибут.
* `delete <id> <key>` - Изтрива атрибут.
* `children <id>` - Списък с децата на елемент и техните атрибути.
* `child <id> <n>` - Достъп до N-тото дете.
* `text <id>` - Извлича съединеното текстово съдържание на елемента.
* `newchild <id>` - Създава нов празен елемент към избран родител.
* `xpath <query>` - Търсене чрез XPath заявка.
* `help` / `exit` - Помощно меню и изход от програмата.

## Тестови Сценарии (Use Cases & Edge Cases)

Следните сценарии демонстрират устойчивостта на парсъра при нормална работа и при среща с невалидни или проблемни данни.

### Сценарий 1: Стандартна работа и XPath (Happy Path)
**Цел:** Проверка дали парсърът коректно зарежда валиден XML, разчита атрибутите и изпълнява сложни XPath заявки.

**Входен файл (`test1.xml`):**
```xml
<university id="su">
    <faculty id="fmi">
        <student id="s1" year="1">John</student>
        <student id="s2" year="2">Alice</student>
    </faculty>
</university>
```
Стъпки за изпълнение:

    open test1.xml

    print

    select s1 year

    xpath faculty/student[@year]

    close

Очакван резултат: Файлът се зарежда успешно. Командата select връща Value: 1. Командата xpath намира и извежда списък с годините на студентите ([0] 1, [1] 2). Паметта се освобождава чисто при close.

### Сценарий 2: Невалидна структура на документа (Множество корени)

**Цел:**: Проверка на защитния механизъм за файлове с повече от един корен (което е невалидно според XML стандарта).

**Входен файл (`test2.xml`):**
```xml
<item id="i1">Book</item>
<item id="i2">Laptop</item>
```
Стъпки за изпълнение:

    open test2.xml

    print

    saveas fixed.xml

Очакван резултат: Парсърът не крашва. При извикване на print се вижда, че програмата автоматично е генерирала служебен родител <document_wrapper>, който обединява двата елемента в паметта. При запазване чрез saveas, структурата се записва коректно в новия файл, изчистена от вътрешните wrapper тагове.

### Сценарий 3: Синтактични грешки и Управление на изключения (Error Handling)

**Цел:**: Проверка дали програмата улавя незатворени тагове и хвърля правилното изключение (ParseException), без да предизвиква изтичане на памет (memory leak).

**Входен файл (`test3.xml`):**
```xml
<root id="main">
    <data id="d1">
</root>
```

(Забележка: Тук тагът <data> се отваря успешно, но липсва неговият затварящ таг </data>)

Стъпки за изпълнение:

    open test3.xml

    print

Очакван резултат: Програмата прекъсва зареждането и извежда грешка: XML error: Parsing error - End of file reached, but there are unclosed XML tags. При последващ опит за print, програмата връща съобщение Error: No file is currently loaded. Please use 'open' first., доказвайки, че повреденото частично дърво е било изчистено от паметта напълно безопасно.

### Сценарий 4: Динамична редакция на дървото и Персистенция (Tree Mutation & Persistence)

**Цел:**: Проверка дали парсърът може безопасно да модифицира съществуващо дърво в паметта (добавяне/триене на атрибути и създаване на нови възли) и да презапише промените директно в оригиналния файл.

**Входен файл (`test4.xml`):**
```xml
<configuration id="config">
    <window id="main_win" width="800" height="600" theme="dark" />
</configuration>
```
Стъпки за изпълнение:

    open test7.xml

    set main_win width 1920 (Актуализира съществуващ атрибут)

    set main_win fullscreen true (Създава напълно нов атрибут)

    delete main_win theme (Изтрива атрибут)

    newChild config (Генерира нов празен елемент вътре в корена)

    save

    close

Очакван резултат: Програмата изпълнява командите без грешка. При извикване на save, оригиналният файл test7.xml се презаписва. Ако го отворим, ще видим, че атрибутът theme липсва, width е променен, добавен е fullscreen="true", а вътре в <configuration> има добавен нов празен таг с автоматично генерирано ID.

### Инструкции за компилация

Проектът не изисква външни зависимости. Може да бъде компилиран с всеки съвременен C++ компилатор, поддържащ стандарт C++11 или по-нов.
